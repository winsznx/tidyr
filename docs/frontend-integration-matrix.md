# TIDYR Frontend Integration Matrix (Phase F0)

Status: baseline discovery for `frontend/production-lifecycle`. Read this before
touching UI code — it fixes what is real, what is stubbed, and what every screen
is allowed to claim.

**Decision (confirmed with product owner 2026-07-18):** build the full frontend
now against **direct chain reads** (viem, no custom backend) for everything
derivable on-chain. Every feature that the PRD assumes a backend service for
(indexed reports, Moralis token discovery, Tenderly simulation, 0x quotes,
WebSocket confirmations) is exposed as an **honest "not yet available" /
degraded state**, never fabricated. No backend code is written in this pass —
that is future, separately-scoped work.

accepts an arbitrary adapter address from any input.

## 3. Shared package reuse (no duplicated business logic)

| Package                                                      | What the frontend imports                                                            | What the frontend must NOT reimplement                                      |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `packages/shared`                                            | `MON_NATIVE_SENTINEL`, `MAX_ACTIONS`, `Address`/`Hex` types, plan/action Zod schemas | Plan shape validation, adapter-kind enum                                    |
| `packages/transaction-review`                                | `executionPlanHash`, `displayManifestHash` (RFC 8785 canonicalization)               | Manifest/plan hashing — must match on-chain `SweepPlanLib.hashPlan` exactly |
| `packages/contracts` (ABIs only, via generated `out/*.json`) | ABI fragments for `SweepExecutor`, `DemoDistributor`, ERC-20                         | Contract addresses (never hardcode — see §4)                                |

`packages/routing` and `packages/execution` are stubs; the frontend package
(`apps/web`) implements its own thin, chain-only routing-read and
execution-monitoring modules under `apps/web/src/lib/`, clearly namespaced so
they are trivial to delete once the real backend packages exist.

## 4. Deployment config — single source of truth

A generated module, `apps/web/src/lib/deployment.ts`, is produced from
`deployments/mainnet.json` (checked into the repo, regenerated by a small
script rather than hand-maintained, so addresses can never drift from the
recorded deployment). No component ever imports a literal `0x...` address.

## 5. Explicit non-goals for this pass (per confirmed decision)

- No Moralis, Tenderly, 0x, or custom indexer integration.
- No WebSocket confirmation feed — polling only, labeled as such.
- No fabricated USD/market pricing — "Executable value" from a live quoter
  call only, or an explicit "no route" / "unavailable" state.
- No claim of "verified" contract source beyond what `deployments/mainnet.json`
  already records from Phase 9.
